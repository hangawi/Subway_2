# 백업·복구·오류 기록·부하 시험 (로드맵 48·49번, 10/19)

## 1. 무엇을 백업하나
- 써브웨이 서버가 가진 것은 **`data/var` (외부 API 하루 사용량 숫자)** 뿐이에요. 주문·알레르기·취향 같은 개인 기록은 **휴대폰에만** 있어 서버 백업에 없어요.
- 앱 코드: Git(main) + 서버의 지난 이미지 `subway-app:prev` (배포 때마다 자동)
- 키(`secrets/subway.env`): 백업하지 않음 (복사본이 늘면 새는 곳이 늘어요). 잃어버리면 각 서비스에서 다시 받아요
- SOPHIA 백업(DB·NAS)과 **섞지 않아요**. 써브웨이 폴더 안 `backups/` 에만 써요

## 2. 매일 백업 (`deploy/backup.sh`)
- 서버 `sophia-core-01` 의 dev 계정 crontab: 매일 04:05
  ```
  5 4 * * * bash /srv/metasolveai/apps/subway/production/app/deploy/backup.sh >> /srv/metasolveai/apps/subway/production/backups/backup.log 2>&1
  ```
- 하는 일: `data/var` 를 `backups/subway-var-날짜.tar.gz` 로 묶음 → 바로 풀리는지 확인 → 체크섬 → **14일 지난 것 지움**
- 상태: 스크립트·시험 복원은 이 컴퓨터에서 확인함 (10/19). **서버 crontab 등록은 예형님 확인 뒤** (10/19 김민지 인수 날이라 서버 변경을 묻기로 함)

## 3. 시험 복원 (`deploy/restore-check.sh`)
- 가장 최근 백업을 **새 빈 폴더**에 풀어 체크섬·파일이 읽히는지만 봐요. 운영 폴더에 덮어쓰지 않아요 (SOPHIA `sqlite-snapshot.py` 와 같은 원칙)
- 실제로 되돌릴 때 (사람이 판단한 뒤):
  1. `cd /srv/metasolveai/apps/subway/production/app/deploy && docker compose stop subway`
  2. `data/var` 를 `data/var.old-날짜` 로 옮기고, 백업을 `data/` 에 풀기 (`tar -xzf backups/… -C data`)
  3. `docker compose up -d subway` → `curl -s http://127.0.0.1:4174/health`

## 4. 오류 기록
- `https://subway.metasolveai.com/health` 의 `counts` (서버를 띄운 뒤 횟수, 내용은 안 남김):
  - `serverErrors` 서버 오류 · `badRequests` 잘못된 요청 · `storeLookupFailures` 매장 찾기 실패(지도 연결) · `aiFailures` AI 실패 · `voiceFailures` 말 받아쓰기 실패 · `requests` 전체
- 서버 오류는 컨테이너 기록에 `SUBWAY_SERVER_ERROR` 로 남아요 (`docker logs subway-prod`, 10MB×3개까지)

## 5. 부하 시험 (`scripts/load-test.ts`)
- **운영 서버에서 돌리지 않아요** (SOPHIA와 같은 서버). 이 컴퓨터에서 써브웨이 서버를 따로 띄우고 외부 연결은 가짜(매장 찾기 120ms, 영업시간 80ms 기다림)
- 한 사람 = 메뉴판 → 추천 → 말로 조건 → 주문서 2번
- 기준: 동시 100명까지 추천 p95 ≤ 2초, 주문서 p95 ≤ 0.5초, 실패 0

| 동시 | 추천 p95 | 말로 조건 p95 | 주문서 p95 | 실패 |
|---|---|---|---|---|
| 20명 | 0.73초 | 56ms | 36ms | 0 |
| 50명 | 0.83초 | 63ms | 53ms | 0 |
| 100명 | 0.97초 | 161ms | 121ms | 0 |
| 200명 (참고) | 1.46초 | 559ms | 408ms | 0 |

- 10/19 이 컴퓨터 결과. 운영 컨테이너는 CPU 1개라 조금 더 느릴 수 있어요. 실제 점심시간에는 외부 연결(카카오·Google) 속도와 하루 한도가 먼저 문제가 돼요 — 매장·영업시간은 5~30분 보관(`src/stores/cache.ts`)으로 줄였어요
